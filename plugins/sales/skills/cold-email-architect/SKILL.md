# Cold Email Architect

A skill for writing cold outbound that gets replies. Use this when a founder or SDR needs a sequence that lands in primary inbox, reads like a human wrote it, and gives the prospect a reason to engage that isn't "hop on a call."

## When to use this skill

- Building a new outbound sequence from scratch (cold list, defined ICP)
- Rewriting a sequence with low reply rates (<3%) where the bottleneck is copy, not list quality
- Adding a new persona to an existing sequence and the rest of the team needs the same structure
- Translating a long-form value prop into the shortest possible email

## When NOT to use this skill

- For warm outreach to people the user has met (a normal email skill is fine)
- When deliverability is the actual problem (low reply rate from a 99 spam score is not a copy problem)
- For nurture-style content emails to inbound leads (use a lifecycle skill, not this one)

## How to run

### Step 1 — Inputs (gather all at once)

1. **Sender** — name, role, company, what makes them legit (one sentence)
2. **ICP** — who's getting this email. Role, seniority, company size, industry. One specific pain they have right now.
3. **Offer** — what the user wants the prospect to do. Book a call? Reply to a question? Reference a case study?
4. **Proof** — one to three pieces of social proof (named customers, results, benchmarks)
5. **Constraints** — banned phrases, banned formats (no Calendly link, no first-name in subject, etc.)

If "ICP" comes back as "B2B SaaS companies", push back. The pain has to be specific or the email won't land.

### Step 2 — Pick the framework

Choose one based on the offer and the proof available:

- **Trigger-Insight-Ask** — when there's a real, recent trigger event (funding, hire, launch). Lead with it. Don't fake one.
- **Loom-Hook-CTA** — when there's video proof and the user can record a 60s walkthrough.
- **Problem-Specific Story-Soft Ask** — when there's a named customer with a quantified result similar to the prospect's situation.
- **Question-Lead-Then-Reveal** — when the offer is consultative and the user wants to start a conversation, not pitch.

State which framework you picked and why before drafting.

### Step 3 — Draft the sequence

Produce a 4-touch sequence:

| Touch | Day | Format | Purpose |
|---|---|---|---|
| 1 | 0 | Email | Initial — framework above |
| 2 | 3 | Email | Reframe — different angle, not "just bumping this" |
| 3 | 7 | LinkedIn or email | Proof drop — case study, customer, result |
| 4 | 12 | Email | Break-up — short, no ask, leave the door open |

Every touch has:
- **Subject line** (≤45 characters, no capitalisation tricks, no emojis unless the user explicitly allows)
- **Body** (≤110 words for touch 1; touches 2–4 ≤80 words each)
- **CTA** (one ask, one question mark — never two)
- **Variant** — one A/B alternative for the body

### Step 4 — Pressure test

After drafting, run this self-check and report it:

- Would this make sense if pasted into a stranger's inbox at 7am? (test for context)
- Is the first sentence about *them* or about *us*?
- Does it survive being read on a phone in the lock screen preview?
- Is there a single, unambiguous next step?

If any answer is no, rewrite that touch before delivering.

## Hand-off

Output the sequence as a clean table the user can paste into Outreach, Apollo, or Lemlist. End with the framework choice and the reasoning, so the user can adapt it for new ICPs without you.
