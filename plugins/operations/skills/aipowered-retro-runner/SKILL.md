# Retro Runner

A skill for running a retro that ends in two specific changes the team commits to — not a wall of post-its and a vague "let's communicate better." Most retros become a vent or a blame round. This skill structures the conversation so the team names the real blockers, picks two to fix, and ships an owner and a date for each.

## When to use this skill

- End of a sprint, a launch, or a quarter
- After a hard ship — a missed deadline, a rough launch, a customer escalation
- For a recurring team retro that has stopped producing changes
- For a cross-functional team that just finished a project together

## When NOT to use this skill

- For an incident — use a postmortem, not a retro
- For a 1:1 — the dynamic is different
- For a team in active conflict — handle the conflict first, then retro

## How to run

### Step 1 — Inputs

Pull from the facilitator:

1. **What we just did** — the sprint, launch, or quarter, in one sentence.
2. **Outcome** — did we hit the goal, miss it, or partially?
3. **Attendees** — names and roles. Limit to the team that did the work.
4. **History** — what came up in the last retro, what got fixed, what didn't.

### Step 2 — Run the format

Four phases, 60 minutes total:

**1. Set the room (5 min)**
- Restate what was done and the outcome.
- Surface last retro's commitments. What got fixed? What didn't? Naming uncompleted commitments resets the bar.
- Rule: speak in behaviors, not personalities. "The handoff was unclear" — not "Sam was confusing."

**2. Silent surfacing (15 min)**
Each person writes, alone, in three buckets:
- What worked (specific, with a name attached when possible)
- What didn't work (specific, behavioral)
- What surprised us (often the most useful column)

No talking. Silent typing only. This kills the loudest-voice problem.

**3. Cluster + pick two (25 min)**
- Read everything aloud, cluster duplicates.
- Vote (3 dots each) on the "didn't work" items.
- Pick the top two. Only two. A retro that picks five fixes nothing.
- For each, the team writes: cause (one sentence), change (one specific thing we'll do differently), owner (one name), by-when (one date).

**4. Commit (15 min)**
Each owner reads their commitment aloud. The team agrees. The facilitator writes them down where the team will see them next sprint.

### Step 3 — Output format

```
# {Team} retro — {date}
**What we did:** {one sentence}
**Outcome:** {hit / partial / miss}

## What worked (top 3)
- {Specific, with names}

## What didn't (top 3, by votes)
- {Specific, behavioral}

## Surprises
- {One sentence each}

## Commitments (2)
1. {Change} — owner: {name}, by: {date}
2. {Change} — owner: {name}, by: {date}

## Last retro's commitments — status
- {Done / not done / partial, with one-line reason}
```

### Step 4 — Rules

- No pronouns in commitments. "We will" is invisible. Use a name.
- No "let's communicate better" or "more alignment." Behavior or it doesn't count.
- The facilitator doesn't bring solutions — the team does.
- No retros without follow-through. If the last two retros' commitments weren't done, the retro is theatre — call it.

## Hand-off

End with a one-line message the facilitator can paste into the team channel: `Retro done — 2 commitments: {1} ({owner}, {date}); {2} ({owner}, {date}). Notes: {link}.` Offer to schedule a 15-minute commitment check halfway to the next retro.
